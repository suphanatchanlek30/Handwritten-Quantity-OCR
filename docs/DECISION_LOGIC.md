# DECISION LOGIC — ระบบตรวจอะไร ใช้ค่าเท่าไหร่ และเมื่อไหร่ต้องให้คนรีวิว

เอกสารนี้อธิบาย **ทุกด่านที่ระบบใช้ตัดสินผล** ตั้งแต่รับภาพจนได้ค่า qty พร้อมเกณฑ์ตัวเลขจริง
ค่าทุกตัวมาจาก `configs/changhouse.yaml` (config หลัก) — ชื่อในวงเล็บ `section.key` คือ key ที่ใช้ปรับค่า
โค้ดที่เกี่ยวข้องระบุไว้ทุกหัวข้อ ถ้าเอกสารกับโค้ดขัดกัน **ให้ถือโค้ดเป็นหลัก** แล้วแก้เอกสาร

> **หลักการออกแบบ:** ระบบ "ไม่เดา" — ถ้าไม่มั่นใจพอจะตอบว่า `needs_review` พร้อมเหตุผล ดีกว่าตอบ `ok` แล้วผิด
> ผลจริงบนภาพสแกน 21 ใบ: **ช่องที่ได้ `ok` ถูกทั้งหมด (98/98)** ช่องที่ผิดทุกช่องถูกส่งให้คนรีวิว

## 1. ภาพรวม: ด่านตรวจทั้งหมด

```text
ภาพ
 │
 ├─[D1] โหลดภาพได้ไหม? ─────────── ไม่ได้ ─▶ ImageLoadError (ข้ามเอกสารนี้)
 │
 ├─[D2] หาตารางเจอและผ่านการตรวจไหม? ─ ไม่ผ่าน ─▶ ทุกช่อง = alignment_failed (ไม่เดาค่า)
 │
 ├─[D3] หาคอลัมน์ qty: อ่านหัวตารางเจอคำว่า qty ไหม? ── ไม่เจอ ─▶ ใช้ตำแหน่ง + ทุกช่องติด qty_column_by_position
 │
 └─ ทุกแถว ────────────────────────────────────────────────────────────────────
     │
     ├─[F1] crop ใช้ได้ไหม (ขนาด/ขอบเขต)? ──── ไม่ได้ ─▶ field_not_found
     │
     ├─[F2] ช่องว่างไหม? ─────────── ว่าง ─▶ blank (value = null)
     │                        └──── ไม่แน่ใจ ─▶ อ่านต่อ + blank_detection_uncertain
     │
     ├─[F3] โมเดลอ่าน 2 แบบ: tight_crop (หลัก) + digit_segments (เทียบ, เมื่อมีหมึก ≥ 2 กลุ่ม)
     │
     ├─[F4] ได้ตัวเลข 1–3 หลักไหม? ───── ไม่ได้ ─▶ invalid_text
     │
     └─[F5] ตรวจความน่าสงสัย 6 ข้อ ─── มีอย่างน้อย 1 ข้อ ─▶ needs_review (+ เหตุผล)
                                     └── ไม่มีเลย ───────▶ ok
```

## 2. ด่านระดับเอกสาร

### D1 — โหลดภาพ (`image_loader.py`)

| ตรวจ | เกณฑ์ | ถ้าไม่ผ่าน |
|---|---|---|
| ไฟล์มีอยู่จริง และเป็นไฟล์ | — | `ImageLoadError` |
| นามสกุล | `.jpg` `.jpeg` `.png` | `ImageLoadError` |
| ขนาดไฟล์ | > 0 byte | `ImageLoadError` |
| เปิดอ่านได้ (ไม่เสีย) | Pillow decode ได้ | `ImageLoadError` |
| ขนาดภาพขั้นต่ำ | กว้างและสูง ≥ 50 px | `ImageLoadError` |

ใน `batch` เอกสารที่โหลดไม่ได้จะถูกข้ามและนับเป็น failure ส่วนเอกสารอื่นทำต่อ

### D2 — หาตาราง (`layout.py`, โหมด `layout.mode: auto`)

ระบบหาเส้นตารางจาก **หมึกพิมพ์เท่านั้น** = pixel ที่มืดกว่าบริเวณรอบๆ (adaptive threshold, block 41 px, C = 12)
**และ** สีไม่สด (saturation ≤ 60) → ลายมือปากกาสีจึงไม่ถูกนับเป็นเส้นตาราง

ตารางที่ยอมรับต้องผ่าน **ทุกข้อ**:

| ตรวจ | เกณฑ์ (ค่าปัจจุบัน) | key |
|---|---|---|
| กรอบผู้สมัครใหญ่พอ | พื้นที่ ≥ 3% ของภาพ | `layout.min_table_area_ratio: 0.03` |
| เส้นต้องเชื่อมกับตารางจริง | เส้นนอนต้องตัดกับเส้นตั้ง ≥ 2 เส้น (และกลับกัน) — ตัดเส้นจุดไข่ปลา/ขอบกระดาษทิ้ง | (ในโค้ด) |
| เส้นต้องยาวพอ | ยาว ≥ 80% ของความกว้าง/สูงตาราง | `layout.final_line_coverage: 0.8` |
| จำนวนคอลัมน์ | เส้นตั้ง ≥ 4 เส้น (= คอลัมน์ ≥ 3) | `layout.min_columns: 3` |
| จำนวนแถว | เส้นนอน ≥ 3 เส้น (หัวตาราง + ≥ 1 แถวข้อมูล) | (ในโค้ด) |
| มีเส้นครอบครบ 4 ด้าน | เส้นนอกสุดห่างขอบกรอบไม่เกิน 8 px | `layout.border_tolerance_px: 8` |
| เส้นไม่ซ้อนกัน | เส้นตั้งห่างกัน ≥ 25 px, เส้นนอนห่างกัน ≥ 30 px (ใกล้กว่านี้รวมเป็นเส้นเดียว) | `min_column_width_px`, `min_row_height_px` |

ไม่ผ่าน → `alignment_failed` เหตุผล `no_table_with_grid_found` — **ทุกช่องไม่มีค่า** (ระบบไม่เดาตำแหน่ง)
บนภาพถ่ายจำลอง 42 ใบ เกิด 2 ครั้ง (ภาพเบลอ + มุมบิดแรง)

จำนวนแถว **ไม่ได้ fix** — อ่านตามเส้นที่เจอจริง ถ้าไม่เท่ากับ `field.expected_rows: 10` จะบันทึกไว้ใน
`results.json → alignment.row_count_note` (เป็นข้อสังเกต ไม่ใช่ error)

> โหมด `layout.mode: template` (ไฟล์ `changhouse_v1/v2.yaml`) ใช้เกณฑ์ต่างออกไป: ต้องเจอเส้นตรงพิกัด template
> ≥ 85% (`alignment.min_line_match_ratio`) ไม่งั้นลองย่อ/ขยายภาพทั้งใบ (`static_scale`) ถ้าผ่านทางนี้ทุกช่องติด
> `alignment_fallback_used`; ถ้าเส้นบางเส้นไม่เจอและต้องใช้ตำแหน่งจาก template ทุกช่องติด `grid_lines_from_template`

### D3 — หาคอลัมน์ qty (`layout.py → locate_qty_column`)

1. ตัด **บรรทัดแรก** ของหัวคอลัมน์ที่คาดว่าเป็น qty (= คอลัมน์ที่ 2 จากขวา, `layout.qty_column_from_right: 2`) แล้วให้โมเดลอ่าน
2. ถ้าข้อความมีคำใน `layout.qty_header_keywords` (`qty`, `จำนวน`) → ใช้คอลัมน์นี้ (ส่วนใหญ่จบที่ขั้นนี้, อ่าน 1 ครั้ง)
   - เทียบแบบ "มีคำนี้อยู่" หรือ **คล้ายกันเกือบเท่ากัน** (ความคล้าย ≥ 0.66 เช่น `qry` นับเป็น `qty`)
3. ไม่ตรง → อ่านหัวทุกคอลัมน์ ถ้าเจอคอลัมน์ที่ตรง **พอดี 1 คอลัมน์** → ใช้คอลัมน์นั้น
4. ไม่เจอ หรือเจอหลายคอลัมน์ → ใช้ตำแหน่ง "ที่ 2 จากขวา" และ **ทุกช่องติด `qty_column_by_position`** (ต้องรีวิว)

คำสั่ง `crop` (ไม่โหลดโมเดล) ใช้ตำแหน่งเสมอ และไม่ติดเหตุผลนี้

### สถานะของเอกสาร

| `status` ของเอกสาร | เมื่อไหร่ |
|---|---|
| `completed` | ประมวลผลครบ (ช่องต่างๆ อาจมี `needs_review`) |
| `completed_with_errors` | มีบางช่องเป็น `recognition_error` หรือ `field_not_found` |
| `alignment_failed` | ด่าน D2 ไม่ผ่าน |
| `crops_only` | คำสั่ง `crop` (ไม่ได้อ่านตัวเลข) |

## 3. ด่านระดับช่อง (ทีละแถว)

### F1 — crop ใช้ได้ไหม (`roi_extractor.py`)

ตัดช่อง qty ระหว่างเส้นตารางแล้ว **หดเข้า 4 px** ทุกด้านเพื่อตัดเส้นขอบ (`roi.crop_margin_px: 4`)

| ตรวจ | เกณฑ์ | ถ้าไม่ผ่าน |
|---|---|---|
| กรอบอยู่ในภาพ | ทั้ง 4 มุมอยู่ในขอบเขตภาพที่ยืดแล้ว | `field_not_found` (`bbox_invalid`) |
| ขนาดพอ | กว้าง ≥ 40 px และสูง ≥ 30 px | `field_not_found` (`crop_too_small`) |

### F2 — ช่องว่างหรือมีลายมือ (`blank_detector.py`)

**ขั้นที่ 1: หาหมึก** ในช่อง (หดเข้าอีก 3 px, `inspect_margin_px: 3`) โดย **เทียบกับสีกระดาษของช่องนั้นเอง**
(`ink_threshold: relative` — ทนภาพเบลอ/ซีด/แสงต่างกัน ใช้ได้กับปากกาทุกสี)

| ชนิดหมึก | เงื่อนไข (pixel) | key |
|---|---|---|
| หมึกมืด (ดำ/น้ำเงินเข้ม/ดินสอ) | ความสว่าง ≤ (ค่ากลางของช่อง − 45) | `dark_min_contrast: 45` |
| หมึกสี (แดง/น้ำเงิน/ส้ม) | ความสดของสี ≥ (ค่ากลางของช่อง + 30) **และ** ความสว่าง ≥ 50 | `color_min_contrast: 30`, `color_min_value: 50` |

แล้วตัดสิ่งรบกวนทิ้ง:
- เส้นยาวบางที่แตะขอบ crop (เศษเส้นตาราง): ยาว ≥ 80% ของด้าน และหนา ≤ 6 px
- จุดเล็กๆ: พื้นที่ < 6 pixel (`min_component_area: 6`)

**ขั้นที่ 2: ตัดสิน**

| ผล | เงื่อนไข | key |
|---|---|---|
| **nonblank** (มีลายมือ) | หมึก ≥ 40 pixel **หรือ** (หมึก ≥ 12 pixel **และ** มีเส้นสูง ≥ 18 px) | `nonblank_min_pixels: 40`, `uncertain_min_pixels: 12`, `min_stroke_height_px: 18` |
| **uncertain** (ไม่แน่ใจ) | หมึก 12–39 pixel และไม่มีเส้นสูงถึง 18 px | |
| **blank** (ว่าง) | หมึก < 12 pixel | |

- กฎ "เส้นสูง ≥ 18 px" มีไว้กันเลข **1 เส้นบางๆ** ซึ่ง pixel น้อยแต่ไม่ใช่ช่องว่าง
- `blank` → `value = null` เสมอ (**ไม่ใช่ "0"**) — เลข 0 ที่เขียนจริงมีหมึกเป็นวงจึงผ่านเกณฑ์ nonblank
- `uncertain` → **ยังส่งให้โมเดลอ่าน** แต่ติด `blank_detection_uncertain` (ต้องรีวิวเสมอ)
- ค่าจริงบนภาพสแกน: ช่องมีลายมือน้อยสุด 96 pixel, ช่องว่างทุกช่อง 0 pixel → ห่างจากเกณฑ์มาก (แยกถูก 210/210)

**ขั้นที่ 3: นับกลุ่มหมึก** (ใช้ประมาณจำนวนหลัก): ก้อนหมึกที่ใหญ่พอ (พื้นที่ ≥ 15 pixel และสูง ≥ 30% ของก้อนที่สูงที่สุด,
`group_min_area: 15`, `group_min_height_ratio: 0.3`) ที่ **ไม่ซ้อนกันในแนวนอน** นับเป็นคนละกลุ่ม
→ ตัวเลขที่เขียนแยกกัน = หลายกลุ่ม, ตัวเลขที่เขียนติดกัน = กลุ่มเดียว (จึงเป็น "ขั้นต่ำ" ของจำนวนหลัก)

### F3 — เตรียมภาพและอ่าน (`preprocessing.py`, `recognizer.py`)

| การอ่าน | ภาพ | ทำเมื่อ |
|---|---|---|
| **tight_crop** (ผลหลัก) | ตัดรอบหมึกพอดี + ขอบขาว 35% ของความสูงหมึก (อย่างน้อย 8 px) | ทุกช่องที่ไม่ว่าง |
| **digit_segments** (ผลเทียบ) | แยกทีละกลุ่มหมึก (ทาสีส่วนอื่นเป็นขาว) อ่านทีละภาพแล้วต่อกัน | เมื่อมีหมึก **≥ 2 กลุ่ม** เท่านั้น (กลุ่มเดียว = ภาพเหมือน tight_crop จึงไม่อ่านซ้ำ) |

ผลจากโมเดลถูก **ถอดใหม่ให้ออกได้แค่ตัวเลข 0–9** (`ocr.digit_constrained_decoding: true`, `digit_decoder.py`)
เพราะโมเดลรู้จัก 18,385 ตัวอักษร และมักอ่านลายมือเป็นตัวอักษรหน้าตาคล้าย เช่น `32`→`BZ`, `64`→`GA`, `95`→`IS`
ผลดิบก่อนถอดเก็บไว้ใน `raw_text` เพื่อตรวจสอบย้อนหลัง

### F4 — เป็นตัวเลขที่ใช้ได้ไหม (`postprocessing.py`)

ค่าที่ยอมรับ: ตัวเลข 0–9 ล้วน ยาว **1–3 หลัก** (`field.min_digits: 1`, `field.max_digits: 3`)
- เก็บเลข 0 นำหน้า (`"007"` ยังเป็น `"007"`), `value_int` แยกให้
- **ไม่มีการเดาแปลงตัวอักษร** แบบ O→0, I→1, S→5 — การแปลงเกิดจาก probability ของโมเดลเท่านั้น (และถูก flag)

ไม่ผ่าน → `invalid_text` พร้อมเหตุผล `empty_prediction` / `empty_prediction_on_nonblank` / `non_numeric_characters` / `too_many_digits`

## 4. ค่า confidence คำนวณอย่างไร

`confidence` = ค่า **digit score** ของผลที่ถูกเลือก (0–1)

```text
สำหรับแต่ละตัวอักษรที่โมเดลอ่านได้ (ช่วงเฟรมใน CTC):
    share = P(ตัวเลขที่เลือก) / (1 − P(ช่องว่าง))      ← สัดส่วนความน่าจะเป็น "ที่ไม่ใช่ช่องว่าง" ที่ตกกับตัวเลขนี้
    char_score = ค่าเฉลี่ย share ของทุกเฟรมในช่วงนั้น
digit score (tight_crop)     = ค่าเฉลี่ย char_score ของทุกหลัก
digit score (digit_segments) = ค่าต่ำสุดของทุก segment   ← segment ที่อ่อนที่สุดเป็นตัวกำหนด
```

- โมเดลมั่นใจว่าเป็นตัวเลขจริง → score ใกล้ 1 (ส่วนใหญ่ 0.95–1.00)
- โมเดลเห็นเป็นตัวอักษร (เช่น "B") แล้วระบบแปลงเป็นตัวเลข → score ต่ำ (มักต่ำกว่า 0.5)
- **score ไม่ใช่ความแม่นยำ** และยังไม่ได้ calibrate กับข้อมูลจริง

## 5. ขั้นตอนตัดสินค่า (decide) ทีละขั้น

โค้ด: `src/qty_ocr/postprocessing.py → decide()` — เรียงตามลำดับที่ทำจริง

```text
0. เตรียม: reasons = เหตุผลระดับเอกสาร (เช่น qty_column_by_position)
           ถ้า F2 = uncertain → เพิ่ม blank_detection_uncertain

1. ทุกการอ่าน error?            → recognition_error (จบ)

2. เลือกค่าตั้งต้น
   ├─ tight_crop เป็นตัวเลขที่ใช้ได้          → ใช้ tight_crop
   ├─ ไม่ได้ แต่ digit_segments ใช้ได้       → ใช้ digit_segments + primary_variant_invalid
   └─ ไม่มีอันไหนใช้ได้                      → invalid_text (จบ)

3. ตรวจตัวเลขเขียนติดกัน (เช่น 79 ถูกอ่านเป็น 7)
   ถอดผลเดิมใหม่แบบ "บังคับเพิ่ม 1 หลัก" แล้วดูว่าความน่าจะเป็นลดลงเท่าไร (penalty, ต่อเฟรม)
   ถ้า penalty ≤ 0.03  (หรือ ≤ 0.06 เมื่อกลุ่มหมึก > จำนวนหลักที่อ่านได้) และผลใหม่ยังเป็น 1–3 หลัก
       → ใช้ค่าที่ยาวขึ้น + possible_merged_digits(เดิม->ใหม่)

4. เทียบกับ digit_segments (ถ้ามี) — ถ้าได้คนละค่า
       → tight_vs_segments_disagree(ค่าที่เลือก vs segments)
       ถ้าขั้น 3 ยังไม่ได้แก้ค่า และจำนวนหลักต่างกัน และ segments มีจำนวนหลัก = จำนวนกลุ่มหมึก
       → เปลี่ยนไปใช้ค่าของ segments (แก้กรณี "11" ถูกอ่านเป็น "1")

5. variant ทดลองอื่น (ปิดอยู่ในค่า default) อ่านได้ค่าอื่นด้วย score ≥ 0.85 → variant_disagreement

6. ผลที่เลือกเคยเป็นตัวอักษรแล้วถูกแปลงเป็นตัวเลข  → letters_mapped_to_digits('BZ'->32)

7. confidence < 0.85                               → low_confidence(score<0.85)

8. ค่าสุดท้ายไม่ใช่ 1–3 หลัก                        → invalid_text (จบ)

9. กลุ่มหมึก > จำนวนหลักของค่าสุดท้าย              → ink_groups_exceed_digits(กลุ่ม>หลัก)

10. มีเหตุผลอย่างน้อย 1 ข้อ → needs_review   /   ไม่มีเลย → ok
```

หมายเหตุสำคัญ:
- เกณฑ์ `low_confidence` ใช้ score ของการอ่านที่ถูกเลือก **ก่อน** ขั้น 3 แก้ค่า (ค่าที่ถูกแก้ด้วยขั้น 3 ต้องรีวิวอยู่แล้ว)
- `letters_mapped_to_digits` ดูเฉพาะผลที่ถูกเลือกใช้ ถ้า segments มีการแปลงแต่ผลที่ใช้คือ tight_crop จะไม่นับ
- ทุกกฎ **เพิ่มเหตุผลได้อย่างเดียว ไม่มีกฎไหนลบเหตุผล** → ช่องจะได้ `ok` ต่อเมื่อไม่ติดข้อใดเลย

## 8. ตัวอย่างจริงทีละขั้น

### ก. `order_form_01` แถว 1 — ค่าจริง 15 → **ok**
- F2: หมึก 523 pixel, 2 กลุ่ม → nonblank, อ่านทั้ง tight_crop และ segments
- tight_crop = `15` score 0.995 (ไม่มีการแปลงตัวอักษร); segments = `15` (ผลดิบ `|5`)
- ขั้น 3: บังคับ 3 หลักได้ `151` penalty 0.232 > 0.03 → ไม่แก้
- ขั้น 4: ตรงกัน, ขั้น 6: ผลที่เลือก (tight_crop) ไม่มีการแปลง, ขั้น 7: 0.995 ≥ 0.85 → **ok**

### ข. `example` แถว 3 — ค่าจริง 79 → **needs_review, ค่าเสนอ 79 (ถูก)**
- F2: หมึก 1,495 pixel แต่ **1 กลุ่ม** (7 กับ 9 เขียนติดกัน) → ไม่อ่านแบบแยกหลัก
- tight_crop = `7` score 0.753
- ขั้น 3: บังคับ 2 หลักได้ `79` penalty 0.021 ≤ 0.03 → ใช้ `79` + `possible_merged_digits(7->79)`
- ขั้น 7: 0.753 < 0.85 → `low_confidence`

### ค. `example` แถว 1 — ค่าจริง 18 → **needs_review, ค่าเสนอ 78 (ผิด แต่ถูกส่งรีวิว)**
- 1 กลุ่มหมึก, tight_crop = `7` score 0.767 (เลข 1 หัวงอถูกเห็นเป็น 7)
- ขั้น 3: บังคับ 2 หลักได้ `78` penalty 0.001 → ใช้ `78` + `possible_merged_digits`; ขั้น 7: `low_confidence`
- ระบบดึงหลักที่หายกลับมาได้ แต่หลักแรกยังผิด — คนรีวิวเห็นเหตุผล 2 ข้อจึงต้องตรวจ

### ง. `arm-1` แถว 3 — ค่าจริง 22 (เลข 2 หางยาว) → **needs_review, ค่าเสนอ 29 (ผิด แต่ถูกส่งรีวิว)**
- 2 กลุ่ม; tight_crop = `29` score 0.649; segments = `29` (ผลดิบ `2f`)
- ขั้น 3: บังคับ 3 หลัก penalty 0.122 → ไม่แก้; ขั้น 4: ตรงกัน; ขั้น 7: 0.649 < 0.85 → `low_confidence`

### จ. `arm-14` แถว 3 — ค่าจริง 11 (เส้นตรงบาง 2 เส้น) → **needs_review, ค่าเสนอ 11 (ถูก)**

## 10. ปรับเกณฑ์อย่างไร และผลกระทบ

| อยากได้ | ปรับ | ผลข้างเคียง |
|---|---|---|
| รีวิวน้อยลง | ลด `ocr.confidence_review_threshold` (เช่น 0.80) | **เสี่ยงค่าผิดหลุดเป็น `ok`** — ต้องมีข้อมูลที่คนตรวจแล้วมายืนยันก่อน |
| ปลอดภัยขึ้น | เพิ่ม threshold (เช่น 0.90) | รีวิวมากขึ้น |
| ดึงหลักที่หายมากขึ้น | เพิ่ม `missing_digit_max_penalty` | เสี่ยงเพิ่มหลักเกินในช่องที่ถูกอยู่แล้ว (ช่องปกติ penalty ≥ 0.054 บนข้อมูลชุดนี้) |
| ลายมือจางถูกมองว่าว่าง | ลด `blank_detection.dark_min_contrast` / `color_min_contrast` | เสี่ยงเงา/ฝุ่นถูกนับเป็นลายมือ |
| ช่องว่างถูกมองว่ามีลายมือ | เพิ่ม `nonblank_min_pixels`, `min_component_area` | เสี่ยงเลข 1 เส้นบางถูกมองว่าว่าง |
| ฟอร์มหัวคอลัมน์เป็นคำอื่น | เพิ่มคำใน `layout.qty_header_keywords` | — |
| ตารางจาง/เล็กหาไม่เจอ | ลด `layout.final_line_coverage` (0.7), `alignment.adaptive_c` (8) | เสี่ยงจับเส้นที่ไม่ใช่ตาราง |

**ที่มาของค่าปัจจุบัน:** เลือกจากการทดลองบนภาพ 21 ใบ + ภาพจำลอง 42 ใบ (ดู `docs/BENCHMARK.md`) — เป็นค่า in-sample
ยกเว้น `confidence_review_threshold: 0.85` ซึ่งเป็นค่าตั้งต้นที่ **ยังไม่ได้ calibrate**

**กฎเวลาปรับ:** ปรับทีละค่า → รันชุดทดสอบ → `python scripts/compare_results.py outputs/baseline_scan <ผลใหม่>` →
ตรวจทุกช่องที่เปลี่ยน ต้องไม่มีช่องที่ **ถูก → ผิด** และต้องไม่มีช่องที่ **ผิดแต่ได้ `ok`** เพิ่มขึ้น
