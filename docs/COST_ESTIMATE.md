# ต้นทุนการรัน PP-OCRv5 (ประเมินขั้นต่ำ) — 2026-10-15

> คำว่า "1 รูป" ในเอกสารนี้ = ใบสั่งสินค้า 1 ใบ (ตาราง 10 แถว ≈ 17 ภาพย่อยที่ส่งเข้าโมเดล) ซึ่งมากกว่ารูปทดสอบ 6 แถวใน Summary Report
> ดังนั้นตัวเลขในเอกสารนี้เป็น **ขอบบน** ของรูป 6 แถว
> อัตราแลกเปลี่ยนที่ใช้: **1 USD = 33.5 บาท** (ช่วง ก.ย.–ต.ค. 2026 อยู่ที่ ~33.1–33.7)
> ราคา cloud = AWS ภูมิภาค US East แบบ on-demand Linux (ภูมิภาคอื่น เช่น สิงคโปร์ แพงกว่าราว 10–30%)

## 1. สรุปสั้น

- **PP-OCRv5 ไม่ได้ฟรี 0 บาท** ตัวโมเดลฟรี แต่ต้องมีค่าเครื่อง ถ้าคิดเฉพาะค่าประมวลผล ต้นทุนอยู่ราว **0.0007–0.002 บาท/รูป**
  (ถูกกว่า Gemini แบบตอบตรงๆ (0.02 บาท/รูป) ประมาณ 10–30 เท่า)
- **ไม่ต้องใช้ GPU**: CPU 1–2 vCPU กับ RAM 2 GB ก็พอ GPU เร็วกว่า แต่ค่าเช่าแพงกว่า ~7 เท่า (ค่าที่ประมาณแบบ "กรณีดีสุด" ของ GPU ในหัวข้อ 3 ทำให้ต้นทุนต่อรูปออกมาใกล้ CPU แต่เป็นตัวเลขที่ยังไม่ได้วัด)
- **ต้นทุนจริงขึ้นกับปริมาณงาน** ถ้าเช่าเครื่องเปิดทิ้งไว้ 24 ชม. แต่มีรูปน้อย ค่าเช่าต่อเดือนจะถูกหารด้วยรูปไม่กี่รูป
  ถ้างานน้อย ควรใช้แบบจ่ายตามการใช้งาน (serverless) หรือเปิดเครื่องเฉพาะตอนรัน

## 2. Spec ขั้นต่ำ (วัดจริงบน MacBook Air M5, ONNX Runtime, CPU)

| รายการ | ผลวัดจริง |
|---|---|
| เวลาต่อรูป, CPU 1 thread | **0.64 วินาที** (ส่วนที่โมเดลอ่าน 0.40 วิ ≈ 23 ms ต่อภาพย่อย ส่วนหาตาราง/ตัดภาพ 0.24 วิ) |
| เวลาต่อรูป, CPU 4 threads | 0.53 วินาที (เพิ่มเธรดได้ประโยชน์น้อย เพราะภาพย่อยเล็กมาก → ใช้ 1 vCPU ต่อ 1 process ก็คุ้มสุด) |
| RAM สูงสุด | **0.60–0.65 GB** (รวม Python + OpenCV + ONNX Runtime + โมเดล) |
| เวลาโหลดโมเดลครั้งแรก | 0.7 วินาที (โหลดครั้งเดียวแล้วใช้ซ้ำ) |
| ขนาดโมเดล | 81 MB |


| | ขั้นต่ำที่รันได้ | แนะนำ |
|---|---|---|
| CPU | 1 vCPU (x86-64 หรือ ARM64) | 2 vCPU |
| RAM | 2 GB | 4 GB |
| Disk | 10 GB (OS + Python + library + โมเดล) | 20 GB |
| GPU | ไม่ต้องใช้ | — |
| OS | Linux / macOS / Windows, Python 3.11 | Linux |

**ข้อควรรู้เรื่องความเร็ว CPU บน cloud:** core ของ M5 เร็วกว่า vCPU บน cloud ทั่วไป
เอกสารทางการของ Paddle วัดได้ 31.21 ms ต่อภาพย่อยบน Intel Xeon Gold 6271C (เครื่องเรา 23 ms)
**ในเอกสารนี้จึงเผื่อว่า cloud ช้ากว่า M5 ประมาณ 3 เท่า → ~2 วินาทีต่อรูปต่อ 1 vCPU** (ประมาณการ ยังไม่ได้วัดบน cloud จริง)

## 3. CPU vs GPU ไหวกี่รูป

| เครื่อง | ความเร็ว (ต่อรูป) | ไหวกี่รูป/ชม. | ไหวกี่รูป/วัน (24 ชม.) | ที่มา |
|---|---|---:|---:|---|
| MacBook Air M5 (เครื่องเรา) | 0.53 วิ, `--workers 2` เร็วขึ้น ~25% | ~6,700–8,400 | ~160,000–200,000 | **วัดจริง** |
| Cloud CPU 1 vCPU | ~2 วิ | ~1,800 | ~43,000 | ประมาณการ |
| Cloud CPU 2 vCPU (2 process) | ~2 วิ ต่อ process | ~3,600 | ~86,000 | ประมาณการ |
| Cloud GPU NVIDIA T4 + 4 vCPU | ส่วนโมเดล ~0.14 วิ (17 × 8.46 ms) แต่ส่วนหาตาราง/ตัดภาพยังใช้ CPU | ~15,000–20,000 | ~360,000–480,000 | ประมาณการจากตัวเลขทางการของ Paddle (ยังไม่ได้ทดสอบบน GPU จริง) |

**ทำไม GPU ไม่คุ้มสำหรับงานนี้:** GPU เร่งได้เฉพาะส่วนที่โมเดลอ่าน (~60% ของเวลา)
ส่วนหาตาราง/ตัดภาพยังวิ่งบน CPU อยู่ดี GPU จะคุ้มเมื่อมีรูปหลายแสนรูปต่อวันอย่างต่อเนื่องเท่านั้น

## 6. ต้นทุนอื่นที่ควรใส่ในเอกสาร

| รายการ | PP-OCRv5 (รันเอง) | ChatGPT / Gemini (API) |
|---|---|---|
| **ค่าคนตรวจ** (มักแพงกว่าค่าประมวลผลมาก) | ระบบบอกเองว่าช่องไหนต้องตรวจ (ภาพสแกน ~20% ของช่อง, ภาพถ่ายยาก IMG_9328 ~63%) ช่องที่ระบบไม่เตือนถูกเกือบหมด | ไม่มีค่าความมั่นใจที่เชื่อถือได้ ต้องสุ่มตรวจหรือตรวจทุกช่อง |
| สูตรค่าคนตรวจ | จำนวนรูป × แถวต่อรูป × % ที่ต้องตรวจ × วินาทีต่อแถว ÷ 3,600 × ค่าแรงต่อชม. | เหมือนกัน แต่ % ที่ต้องตรวจสูงกว่า |
| ความเป็นส่วนตัวของข้อมูล | รูปไม่ออกนอกเครื่อง | ส่งรูปไปเซิร์ฟเวอร์ผู้ให้บริการ |
| ค่าพัฒนา/ดูแลระบบ | ต้องดูแลเครื่อง, deploy, อัปเดต | น้อยกว่า (เรียก API อย่างเดียว) |
| ราคาเปลี่ยนได้ไหม | ไม่เปลี่ยน (ขึ้นกับค่าเช่าเครื่อง) | ผู้ให้บริการเปลี่ยนราคา/โมเดลได้ |
| Fine-tune | ค่า GPU ไม่มาก (T4 Spot ~11 บาท/ชม. × ไม่กี่ชั่วโมง) แต่ค่าเก็บ/ติดป้ายข้อมูลลายมือจริงเป็นต้นทุนหลัก | ทำไม่ได้หรือแพง |

## 7. ข้อจำกัดของตัวเลขชุดนี้

- ความเร็วบน cloud และบน GPU เป็นการ **ประมาณการ** จากตัวเลขที่วัดบน M5 และตัวเลขทางการของ Paddle ยังไม่ได้วัดบนเครื่องจริง
  ถ้าจะยืนยัน ให้เช่า c7g.large 1 ชม. (~2.5 บาท) แล้วรัน `scripts/profile_pipeline.py` ด้วยคำสั่งเดียวกับข้างบน
- ราคา AWS เป็นของ ต.ค. 2026 จากเว็บรวบรวมราคา (Vantage) และหน้าราคาทางการของ AWS Lambda ควรเช็กอีกครั้งก่อนใช้จริง
- Lambda: ตัวเลขยังไม่รวม cold start (โหลด library + โมเดลครั้งแรก ประมาณหลายวินาที; เฉพาะส่วนโหลดโมเดลวัดได้ 0.7 วินาที)
- ราคา ChatGPT / Gemini ใช้ตามตาราง Summary Report เดิม ไม่ได้ตรวจซ้ำ
